# 电商运营助手 · Front

基于 **React + TypeScript + Vite** 的单店铺运营前端。项目全部位于当前目录，后端尚未包含在本项目中。

## 启动

使用 Node.js 22.12+（当前开发环境为24.x）。在当前目录执行：

```powershell
npm ci
npm run dev
```

默认访问 http://127.0.0.1:5173 。端口被占用时会明确报错，不会静默换端口。

首次安装后复制配置：

```powershell
Copy-Item .env.example .env.local
```

`.env.local` 示例：

```dotenv
VITE_API_BASE_URL=/api/v1
API_PROXY_TARGET=http://127.0.0.1:8000
```

代理目标必须是实际 FastAPI 服务地址，不包含 `/api/v1` 后缀。更改开发代理后重启前端开发服务。后端必须先初始化管理员账号；本项目前端不内置默认账号或自助注册。

## 构建与检查

```powershell
npm run typecheck
npm test
npm run contract:check
npm run build
```

生产构建位于 `dist/`。该目录由静态服务器提供，`/api/` 由反向代理转发给 FastAPI；静态服务器需将不存在的前端路由回退到 `index.html`。`API_PROXY_TARGET` 仅用于 Vite 开发服务器，不会随静态构建部署。CentOS 7 服务器只需提供构建后的静态文件，不能直接照搬本地Node版本安装步骤；完整服务部署留待后端阶段确定。

## 已实现的页面与流程

- 登录、退出、会话恢复、失效处理、角色与专项操作入口。
- 工作台：真实店铺统计、待办、最近轮次、运营路径。
- 商品列表：搜索、状态过滤、分页、新增和编辑。
- 商品详情：商品/竞品、运营轮次、诊断、主图、脚本、标题、任务、素材、链接、投放/实验、经营/复盘。
- SKU及库存：规格维护、增量库存调整、预警、流水、店铺库存总览。
- 竞品：手动资料、公开链接解析的创建/启动/查看、监控及快照。
- 运营轮次：诊断选定、快照读取、结束/取消、复盘动作采纳与下一轮。
- 创意：至少3候选、结构化编辑、选用/归档、提交真实图片或视频生成任务。
- 任务：轮询、事件、错误、重试和取消；任务受理不等于生成成功。
- 素材：私有文件预览、人工上传登记、审核、评分标签、同方案批量审核及同步。
- 投放：建议编辑、确认/驳回与历史、实验草案、计划确认、人工执行状态记录。
- 经营与复盘：日粒度数据、汇总指标、更正/作废、复盘编辑与修订。
- 导入：四类模板下载、文件上传、预览、错误行、显式提交、部分成功结果。
- 管理：单店铺信息、平台账号占位、用户、模型/系统/队列配置、维护任务、审计记录。

## 数据原则

**没有用于填充页面的硬编码商品、库存、素材、经营指标或假登录账号。** 数据来自契约定义的真实接口。未登录、加载中、空结果、连接失败和权限不足各自展示对应状态，不把网络错误当作0或空数据。

表单的数量、模式等初始值只来自契约默认值；商品名称、价格等业务字段不会自动填入示例。设置中的“演示初始化”是原需求要求的真实后端管理操作，只在管理员明确点击确认时调用；页面不会自动执行，也没有浏览器内演示数据。

`tests/` 中的隔离测试输入和网络替身只供测试运行，不被运行时页面导入。

## 工程结构

```text
src/
  api/             真实请求、响应类型、128接口元信息、Schema
  app/             会话、权限、查询缓存、通知、应用布局
  components/      表单、对话框、表格、文件预览及操作入口
  lib/             中文标签、金额/时间/比率显示
  pages/           各业务页面与商品运营模块
contracts/         原版OpenAPI与中文接口契约
docs/              交接、联调限制、设计说明和浏览器截图
tests/             请求、权限与表单校验测试
scripts/           契约同步及一致性检查
dist/              构建产物
```

## 契约和后端衔接

`contracts/openapi.json` 与 `contracts/openapi.yaml` 是前一阶段的接口契约副本。所有业务接口统一经 `src/api/client.ts` 调用，发送 Bearer、Idempotency-Key 与 If-Match；HTTP 412不会自动覆盖他人修改。文件通过真实上传接口存入后端管理的MinIO，通过短期签名URL预览。

前端使用结构化表单呈现契约对象，不要求运营人员在JSON文本框中编写方案。非管理员无法读取模型配置，媒体生成表单为其保留管理员提供配置编号的入口；见 `docs/INTEGRATION.md`。后续完善后端时建议提供仅包含可用模型能力的安全读取接口，不能直接放开管理配置。

本阶段完成前端实现与静态/单元校验。真实登录、生成供应商、MinIO、导入事务、预算约束与完整双轮业务闭环，需后端按契约部署后进行集成验收，不把当前结果当作后端验收通过。
